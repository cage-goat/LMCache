## 对比结果

1. 原版：Worker B 进程一直存活，但约 63.3 秒后被回收，日志为 pinged=False。
   空闲 90 秒后首次请求遭遇缺失注册，RETRIEVE 被拒绝；v0.5.6 降级重算后仍返回 HTTP 200 和 BLUE-4732。
2. 补丁版：同样空闲 90 秒后注册仍在，实际从 A 写入的缓存读取 1536 tokens（6 个 chunk），返回 BLUE-4732。
   A 的冷算、原版 B 的降级重算、补丁版 B 的缓存命中输出一致。
3. 启动保护：CUDA Graph 开启，Server 确认已收到 PING、尚无 Transfer，且 API 尚未 ready。
   暂停整个测试 Worker 进程组 45 秒（正常超时 30 秒、宽限期 90 秒）后，注册仍在；恢复后完成 CUDA Graph capture 并成功返回首个请求。
4. 正常死亡清理：补丁版完成真实传输后，直接 SIGKILL Worker B，约 31.1 秒后被回收；日志确认 pinged=True、transfer_activity=True。
